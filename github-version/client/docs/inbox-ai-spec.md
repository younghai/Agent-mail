# Inbox AI 기능 정의

- 상태: 검토용 초안
- 대상: 기존 Cloudflare 기반 Agent Mail의 Inbox
- 목적: 고객 메일을 이해하고, 요청사항과 누락 정보를 정리해 사용자가 검토할 답변 초안을 만든다.
- 구현 상태: 이 문서는 기능 정의이며, 기능 구현 완료를 의미하지 않는다.

## 1. 사용자가 지정한 우선 범위

1. 메일 요약
2. 답변 메일 초안 작성
3. 고객 요청사항 구조화
4. 필요한 요건 중 빠진 항목과 확인할 질문 제안

실제 메일 발송은 우선 제외한다. 자동 발송, 예약 발송, 발송 승인 연동,
SMTP 및 발송 서비스 설정, 발송 테스트는 이번 범위에 포함하지 않는다.
기존 발송 코드는 이 정의 작업에서 삭제하거나 수정하지 않는다.

## 2. 해결할 문제

메일 원문과 이전 대화에 고객 요청이 흩어져 있어 담당자가 요청을 빠뜨리거나,
이미 받은 정보를 다시 묻거나, 확인하지 않은 조건을 답변에 포함할 수 있다.
AI는 이를 정리하는 보조 도구이며, 고객과의 약속이나 업무 결정을 대신하지 않는다.

## 3. 제안하는 기본 사용 흐름

아래 실행 방식과 화면 구성은 구현 전 검토할 제안이다.

1. Inbox에서 메일을 선택한다.
2. 사용자가 `AI 분석`을 실행한다.
3. 선택한 메일과 같은 대화의 이전 메일을 분석한다.
4. 요약, 고객 요청, 확인할 사항을 같은 패널에서 보여준다.
5. 사용자가 결과를 수정하거나 내부 확인 정보를 보충한다.
6. 사용자가 `답변 초안 작성`을 실행한다.
7. 생성된 초안을 편집하고 저장하거나 복사한다. 발송은 하지 않는다.

초기에는 자동 실행보다 명시적인 사용자 실행을 기본으로 제안한다.
새 메일이 도착하면 기존 결과가 최신 대화를 반영하지 않았음을 알리고,
재분석을 제공한다. 사용자가 수정한 결과나 초안을 자동으로 덮어쓰지 않는다.

## 4. 분석에 사용하는 정보

- 선택한 메일의 제목, 본문, 발신자, 수신 시각
- 같은 메일함·같은 대화에 속한 이전 메일
- 사용자가 직접 보충한 업무 정보
- 실제 내용을 추출한 첨부파일이 있는 경우 그 내용과 출처

첨부파일 이름을 본 것과 내용을 읽은 것을 구분한다. 읽지 못한 첨부파일은
분석에서 제외되었다고 표시한다. 임의의 타 고객 대화나 외부 서비스 정보를 섞지 않는다.
분석 범위를 초과해 일부 대화를 제외한 경우에도 제외 사실을 표시한다.

## 5. 기능별 정의

### 5.1 메일 요약

다음 내용을 간결하게 정리한다.

- 고객이 원하는 결과
- 이번 메일의 주요 내용
- 이전 대화와 비교해 새로 추가되거나 바뀐 내용
- 명시된 기한과 조건
- 담당자가 다음으로 확인할 일

각 핵심 사실에는 근거 메일과 원문 부분을 연결한다. 고객의 희망 조건과
이미 합의된 조건을 구분한다. 원문에 없는 긴급성이나 합의를 만들어내지 않는다.

### 5.2 고객 요청사항 구조화

메일 하나에 요청이 여러 개 있으면 요청별로 나눈다.

| 항목 | 의미 |
|---|---|
| 요청 내용 | 고객이 요구한 일 |
| 요청 유형 | 견적, 주문, 일정 변경, 문의 등 |
| 대상 | 제품, 서비스, 프로젝트 또는 주문 식별 정보 |
| 조건 | 수량, 사양, 장소, 예산 등 메일에 실제 등장한 조건 |
| 희망 기한 | 고객이 제시한 날짜 또는 기간 |
| 현재 확인 상태 | 확인됨, 미확인, 정보 충돌, 해당 없음 |
| 근거 | 원문 메일과 관련 문장 |

위 항목 모두를 모든 요청의 필수 요건으로 취급하지 않는다.
필드마다 메일 원문, 사용자 입력, AI 제안 중 정보의 출처를 구분한다.
명확하지 않은 값은 추정값으로 채우지 않고 미확인으로 남긴다.

### 5.3 누락 요건과 확인 질문 제안

요청을 처리하려면 무엇을 더 알아야 하는지 제안한다.

| 항목 | 의미 |
|---|---|
| 확인할 정보 | 빠졌거나 모호하거나 서로 충돌하는 내용 |
| 필요한 이유 | 이 정보가 어떤 판단에 필요한지 |
| 기준 | 적용한 요청 유형의 요건 또는 AI가 제안한 확인 사항 |
| 중요도 | 답변 전에 확인 필요 / 있으면 도움 됨 |
| 확인 대상 | 고객에게 질문 / 내부 담당자 확인 / 첨부자료 확인 |
| 제안 질문 | 고객 또는 담당자가 답할 수 있는 구체적인 질문 |
| 처리 상태 | 미해결, 해결, 해당 없음 |

판단 규칙:

- 요청 유형별로 필수·선택·조건부 요건을 구분한다.
- 적용할 업무 기준이 없으면 필수라고 단정하지 않고 확인 제안으로 표시한다.
- 이전 대화에서 이미 확인된 내용은 다시 누락으로 표시하지 않는다.
- 정보가 상충하면 한 값을 임의 선택하지 않고 충돌 항목으로 표시한다.
- 사용자가 정보를 보충하면 해당 항목을 갱신하고 초안에도 반영한다.
- 내부에서 확인할 사항을 고객에게 무조건 묻지 않는다.

### 5.4 답변 메일 초안

요약과 구조화된 요청, 사용자가 확인한 정보를 기반으로 작성한다.

- 필요한 정보가 충분하면 고객 요청에 대한 답변 초안을 만든다.
- 핵심 정보가 부족하면 확인 질문을 포함한 초안을 만든다.
- 메일 원문과 사용자 입력에 없는 가격, 재고, 일정 확약, 정책을 만들지 않는다.
- 고객에게 물어볼 질문과 내부 담당자의 메모를 분리한다.
- 원문의 언어를 기본으로 제안하되 사용자가 언어와 말투를 바꿀 수 있도록 한다.
- 사용자 수정본을 보존하고 재생성 결과와 구분한다.
- 저장·복사·재생성만 제공한다. 이 기능에서 발송을 실행하지 않는다.

내부 확인이 끝나지 않은 내용은 초안 옆의 주의 사항으로 표시하고,
고객에게 전달할 본문에 내부 메모를 자동 삽입하지 않는다.

## 6. 화면 구성 제안

기존 Inbox 원문 화면과 AI 패널을 유지하고 패널 안에 다음 내용을 배치한다.

1. 요약
2. 고객 요청사항
3. 확인할 사항
4. 답변 초안

사용자는 근거 원문 열기, 분석 결과 수정, 확인 정보 입력, 재분석,
초안 편집·저장·복사를 할 수 있다. 별도 대시보드나 CRM 개편은 이번 범위가 아니다.

## 7. 결과 상태와 오류 처리

- 미분석
- 분석 중
- 분석 완료
- 일부 분석 완료: 누락된 자료나 실패한 분석 단계를 표시
- 분석 실패: 원인 안내와 재시도 제공
- 갱신 필요: 분석 이후 새 메일이나 사용자 정보 변경이 있음

분석 실패를 빈 결과나 '누락 없음'으로 표시하지 않는다.
요약·요청 추출·누락 판단은 성공했지만 초안 생성이 실패한 경우,
성공한 결과는 유지하고 초안만 재시도할 수 있도록 한다.

## 8. AI 권한과 처리 원칙

- 분석 권한은 사용자의 메일함 접근 권한을 넘지 않는다.
- 메일과 첨부파일의 문구는 분석 대상 데이터이지 AI의 운영 지시가 아니다.
- 이 Inbox AI 흐름에서 발송 도구/API를 호출하지 않는다.
- 초안 저장이 발송이나 발송 승인으로 해석되지 않도록 한다.
- 사실 추출과 제안을 구분하고, 근거가 없는 내용을 사실로 제시하지 않는다.
- 사람이 수정한 내용은 보존한다.

## 9. 완료 판단 기준

1. 여러 요청이 담긴 메일에서 요청을 각각 분리하고 근거를 표시한다.
2. 원문에 없는 값은 미확인으로 표시하고 만들어내지 않는다.
3. 이전 대화에서 확인한 내용을 누락으로 다시 제안하지 않는다.
4. 상충하는 조건은 충돌로 표시하고 구체적인 확인 질문을 제안한다.
5. 사용자가 보충한 정보가 누락 상태와 다음 초안에 반영된다.
6. 첨부파일을 읽지 않았다면 읽었다고 주장하지 않는다.
7. 새 메일이 도착하면 분석 결과의 최신 여부를 구분한다.
8. 재분석·재생성이 사용자의 수정본을 조용히 덮어쓰지 않는다.
9. 분석 실패와 '확인할 사항 없음'을 구분한다.
10. 분석·초안 작성·저장·복사 과정에서 발송 호출이 발생하지 않는다.

## 10. 기존 코드와의 연결

소스 확인 기준으로 `workers/agent/`에는 분류, 초안 작성, 검토 흐름이 있다.
`app/components/AgentPanel.tsx`의 Analysis 탭은 현재 고정 안내 문구를 보여준다.
기존 Cloudflare 구조를 유지하며 실제 분석 결과를 연결하는 방향을 우선한다.
기존 초안 흐름이 있다는 사실은 이 문서의 요구사항이 이미 충족됐다는 뜻이 아니다.

제안 구현 순서는 다음과 같다.

1. 분석 결과 형식과 원문 근거 연결을 정의한다.
2. 요약과 요청사항 구조화를 구현한다.
3. 요청 유형별 요건과 누락 제안, 사용자 보충 기능을 연결한다.
4. 확인된 결과를 기반으로 초안 작성·편집·저장을 연결한다.
5. Inbox에서 전체 흐름과 발송 호출 금지를 검증한다.

## 11. 이번 범위 밖

실제 발송, 자동 답장 발송, 예약 발송, 발송 승인 워크플로,
SMTP 및 발신 도메인 설정, DNS 변경, 운영 배포, 외부 CRM 동기화,
모든 첨부 형식에 대한 OCR·파서 구축, 신규 멀티에이전트 플랫폼 구축.
