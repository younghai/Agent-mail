2026-06-04 Agent Mail Operational Contracts

Scope

대상 폴더는 v1-present-release/github-version와 v1-present-release/docker-version입니다. 변경 범위는 backend API compatibility, inbound mail idempotency, AI workflow observability, Docker runtime hardening, CI/documentation alignment입니다.

Applied Changes

  • React UI가 호출하던 agent-feedback, approvals, admin/cost, segments, admin/sla, reply, forward API를 Mail Server에 추가했습니다.
  • 004_operational_contracts.sql로 provider/message identity, draft approval, agent feedback, AI jobs schema를 추가했습니다.
  • Webhook/SMTP 수신 저장을 mailbox_id + provider + provider_message_id 우선, mailbox_id + message_id fallback 기준의 upsert 흐름으로 바꿨습니다.
  • AI workflow는 summary, timeline, task_extraction, draft_generation job으로 기록되고 Admin overview/UI에서 최근 workflow job을 볼 수 있게 했습니다.
  • client Dockerfile은 dev server 대신 production build 후 vite preview를 실행하도록 변경했습니다.
  • CI는 Mail Server test, React typecheck, React production build, Python checks를 포함하도록 맞췄습니다.

Service Flow

flowchart TD
  inbound[Inbound SMTP/Webhook] --> dedupe{Known provider_message_id or message_id?}
  dedupe -- yes --> existing[Return existing email id
No duplicate event]
  dedupe -- no --> insert[Insert email with provider identity]
  insert --> queue[Publish new_email event]
  queue --> agent[AI Agent workflow]
  agent --> job[ai_jobs: draft_generation status]
  agent --> draft[Draft email with approval_state]
  draft --> approvals[Approvals API/UI]
  job --> admin[Admin AI workflow jobs table]
  ui[React UI] --> compat[Mail Server compatibility routes]
  compat --> reply[Reply/Forward]
  compat --> feedback[Agent Feedback]
  compat --> reports[Cost/SLA/Segments]

Remaining Risks

Docker daemon이 꺼져 있어 실제 이미지 빌드는 확인하지 못했습니다. AI workflow job은 네 가지 타입 모두 실행되지만, 실패 job을 UI에서 재시도하는 requeue action은 아직 별도 작업입니다.
